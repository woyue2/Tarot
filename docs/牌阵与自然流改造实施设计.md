# 牌阵与自然流改造实施设计

> 状态：第一阶段已实现并验证；牌阵库扩展、传统布局与全局默认配置待完成。
> 最后更新：2026-08-08。

---

## 1. 已确认的产品模型

- **牌阵（Spread）**只决定结构：位置、抽牌张数与布局。牌的张数只由牌阵决定，不存在“自由形式”牌阵或用户任意指定张数的模式。
- **last-dance**是所有解读的基础风格：逐牌、故事线、生活化且有共情力的解释。
- **能量流（`energyFlow`）**是附加解读层，不是牌阵。开启后，在 last-dance 基础上增加跨牌模式、能量流、整体主题和整体阅读。
- **评分（`scoring`）**是独立开关。目前只允许在 `five_card_timeline_v1` 上开启；它可以与 `energyFlow` 同时开启。
- 默认入口维持现有体验：`五张时间流 + last-dance + scoring=true + energyFlow=false`。
- 高级入口允许选择牌阵；其初始值为 `scoring=false`、`energyFlow=true`，用户仍可在该入口中修改两个开关。

组合规则：

| scoring | energyFlow | 输出 |
|---|---|---|
| true | false | 基础 last-dance 解读 + 动量/价值解读 |
| false | false | 基础 last-dance 解读 |
| false | true | 基础解读 + 能量流 + 整体主题 + 跨牌模式 + 整体阅读 |
| true | true | 基础解读 + 动量/价值解读 + 能量流完整输出 |

唯一的限制是：不支持评分的牌阵不能开启 `scoring`。

## 2. 当前实现范围

### 2.1 已实现的牌阵

牌阵注册表位于 `packages/core/src/spreads.ts`。

| ID | 名称 | 张数 | 评分 | 状态 |
|---|---|---:|---|---|
| `five_card_timeline_v1` | 五张时间流 | 5 | 支持 | 已实现；默认入口使用 |
| `single` | 单张牌 | 1 | 不支持 | 已实现；高级入口可选 |
| `triple` | 圣三角 | 3 | 不支持 | 已实现；高级入口可选 |

当前所有牌阵均为 `row` 布局；牌阵位置名称会进入抽牌、揭晓和模型输入。

```ts
export interface SpreadPosition {
  index: number;
  name: string;
  hint?: string;
}

export interface Spread {
  id: string;
  name: string;
  description: string;
  positions: readonly SpreadPosition[];
  supportsScoring: boolean;
  layout: "row" | "grid" | "cross" | "z" | "circle";
}
```

### 2.2 已实现的运行时配置

`ReadingService.createReading` 接收并保存以下配置；省略时使用默认入口的兼容默认值：

```ts
{
  question: string;
  mode: "manual" | "random";
  spreadId?: string;      // 默认 five_card_timeline_v1
  scoring?: boolean;      // 默认 true
  energyFlow?: boolean;   // 默认 false
  folderId?: string;
}
```

运行时从注册表取得牌阵定义，不信任 UI 传入的牌阵元数据。手动和随机抽牌均按 `spread.positions.length` 抽取；确认、部分选牌和揭晓也使用同一张数约束。

`StoredReading` 保存 `spreadId`、`scoring` 和 `energyFlow`。桌面 SQLite 已增加对应列并对旧数据库执行 `ALTER TABLE` 迁移；旧记录读取时回退为五张时间流、评分开启、能量流关闭。移动端 localStorage 和 R2 直接持久化该对象，因此新增字段会随记录同步。

### 2.3 已实现的能量流

`packages/core/src/patterns.ts` 会在 `energyFlow=true` 时，对已抽出的牌做本地聚合：

- 大阿尔卡那 / 小阿尔卡那数量；
- 权杖、圣杯、宝剑、星币分布；
- 重复数字；
- 重复视觉符号；
- 牌面人物或画面的朝向序列。

这些事实以 `patterns` 写入模型输入。模型不负责猜测统计结果，而是解释它们与提问者处境的关系。

```text
牌阵与抽牌结果
  → 本地聚合 patterns（仅 energyFlow）
  → last-dance 基础提示词
  → 追加评分指令 / 能量流指令
  → 条件化 JSON Schema
  → 条件化解读输出
```

### 2.4 已实现的 Provider 契约

Provider 通过 `buildOutputSchema`、`buildJsonStructurePrompt` 和 `buildSystemPrompt` 根据输入动态生成输出要求：

- `cards` 的最小、最大长度等于当前牌阵张数；
- `scoring=true` 时强制 `momentumInterpretation` 与 `valueInterpretation`；
- `energyFlow=true` 时强制 `energyFlow`、`overallTheme`、`patterns`、`holisticReading`；
- 响应经 Zod 解析后，再以当前输入进行条件校验，防止模型漏掉模式专属字段。

输出不以模型返回的开关作为真相；UI 以已保存的 Reading 配置和实际存在的输出字段决定展示。

### 2.5 已实现的 UI

桌面端与移动端均已完成：

1. 默认入口保留“五张时间流”的原有文案与行为。
2. 新增“高级解读设置”，可选择当前三种牌阵。
3. 高级设置默认能量流开启、评分关闭；五张时间流可重新开启评分。
4. 选牌页根据牌阵显示正确的 `已选 X / N`、卡槽数和确认条件。
5. 解读页按返回字段显示评分区块和能量流整体阅读区块。

## 3. 尚未完成的事项

### 3.1 多种牌阵：已完成基础三种，尚未完成牌阵库扩展

“可支持多牌阵”的能力、动态张数和高级入口已经完成；但**牌阵内容库尚未完整录入**。当前只提供五张时间流、单张牌、圣三角。

以下仍待从 `docs/塔罗牌阵大全_适用场景与使用方法.txt` 选择并录入：

- 凯尔特十字及其他核心牌阵；
- 三张牌的多种位置预设；
- 恋爱、决策、事业等场景化牌阵；
- 每个牌阵的说明、位置提示和适用场景。

新增固定牌阵只需要在 `SPREADS` 加入位置定义；运行时抽牌、模型 Schema 和基本 UI 会自动使用其张数。若该牌阵需要特殊视觉布局，则还要完成下一项。

### 3.2 非线性布局尚未完成

注册表已经预留 `grid`、`cross`、`z`、`circle`，但 UI 当前只按行展示。凯尔特十字、十字、Z 字、圆形等牌阵需要在 `CardRevealStage` 和移动端揭晓页实现按 `layout` 渲染的布局组件。

### 3.3 全局配置默认值尚未持久化

当前“配置”是每次创建 Reading 时的参数，且高级入口提供可见开关；运行时 API 也允许调用方传入任意合法组合。

尚未实现“应用设置中的全局默认值”，例如让用户设置“以后所有新解读默认开启能量流”。若需要这一能力，应在桌面 preferences 与移动 settings 中保存：

```ts
{
  defaultSpreadId: string;
  defaultScoring: boolean;
  defaultEnergyFlow: boolean;
}
```

创建页面应以这些默认值初始化；默认入口是否仍固定为传统五张评分模式，需要作为产品决策保留优先级。

### 3.4 评分适用范围尚未扩展

动量/价值公式仍是五张时间流专属加权公式。即使未来新增五张牌阵，也不应自动启用评分；需先确认该牌阵的位置语义与公式假设一致，才可将其 `supportsScoring` 设为 `true`。
