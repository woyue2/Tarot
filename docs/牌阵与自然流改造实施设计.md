# 牌阵与自然流改造实施设计

> 状态：设计稿，待评审后落地。
> 基于讨论结论：自然流不是独立牌阵，而是最后一舞风格 + 能量流/跨牌模式/整体读；牌阵、方法论风格、评分是三个正交维度。

---

## 1. 设计结论摘要

- **牌阵（Spread）**：只决定结构（位置、张数、布局），不影响风格。
- **自然流开关（naturalFlow / energyFlow）**：用户-facing 的单一布尔开关。关闭 = 最后一舞风格；开启 = 自然流风格（在最后一舞基础上加入能量流、跨牌模式、整体读）。
- **评分（scoring）**：独立开关，目前仅支持默认 5 张牌阵 `five_card_timeline_v1`，且与自然流互斥。
- **自由形式（freeform）**：牌阵的一种（`positions: []`），与任意风格开关都可组合。

---

## 2. 概念模型：三个正交维度

```
┌─────────────┐     ┌─────────────────────────────┐     ┌─────────────┐
│   Spread    │     │         Style Switch        │     │   Scoring   │
│  （牌阵结构） │  ×  │  naturalFlow: boolean       │  ×  │  boolean    │
│             │     │  false=last-dance, true=flow│     │             │
└─────────────┘     └─────────────────────────────┘     └─────────────┘
         │                       │                            │
         └───────────────────────┴────────────────────────────┘
                                 │
                         ┌───────▼────────┐
                         │  Interpretation │
                         │    Output       │
                         └─────────────────┘
```

组合规则：

| naturalFlow | scoring | spread | 输出字段 |
|---|---|---|---|
| false | true | five_card_timeline_v1 | 基础字段 + `calculation` + `momentumInterpretation` + `valueInterpretation` |
| false | false | 任意 | 基础字段 + storyline |
| true | false | 任意 | 基础字段 + `energyFlow` + `overallTheme` + `patterns` + `holisticReading` |
| true | true | 任意 | **非法**，校验失败 |

### 3.2 输入契约

修改 `packages/core/src/schemas.ts`：

```ts
const spreadSchema = z.object({
  id: z.string(),
  name: z.string(),
  positions: z.array(z.object({ index: z.number(), name: z.string(), hint: z.string().optional() })),
  supportsScoring: z.boolean(),
});

const scoreSchema = z.object({
  semantic: z.number(),
  dynamic: z.number(),
  rank: z.number(),
  final: z.number(),
  basis: z.string().min(1),
  scoreTableVersion: z.string().min(1),
});

const calculationSchema = z.object({
  formulaVersion: z.string().min(1),
  momentum: z.number(),
  momentumLabel: z.string().min(1),
  value: z.number(),
  valueLabel: z.string().min(1),
});

export const interpretationInputSchema = z.object({
  readingId: z.string().min(1),
  contentVersion: z.string().min(1),
  question: z.string().min(1),
  spread: spreadSchema,
  naturalFlow: z.boolean(),               // 新增：风格开关
  scoring: z.boolean(),                   // 新增：评分开关
  draw: z.object({ mode: z.enum(["manual", "random"]), confirmed: z.literal(true) }),
  cards: z.array(z.object({
    id: z.string().min(1),
    name: z.string().min(1),
    orientation: z.enum(["upright", "reversed"]),
    position: z.number().int().min(1),
    positionName: z.string().min(1),
    visualDescription: z.string().min(1),
    symbols: z.array(z.string()),
    direction: z.string(),
    score: scoreSchema,
  })),
  calculation: z.optional(calculationSchema),     // 改为 optional
  patterns: z.optional(z.object({                 // 自然流时填充
    majorMinorRatio: z.string(),
    suitDistribution: z.string(),
    repeatedNumbers: z.array(z.string()),
    repeatedSymbols: z.array(z.string()),
    directionFlow: z.string(),
  })),
  methodology: z.object({ version: z.string().min(1), style: z.string().min(1) }),
  promptVersion: z.string().min(1),
  outputLanguage: z.literal("zh-CN"),
}).superRefine((input, context) => {
  const spread = input.spread;
  const expectedCount = spread.positions.length === 0
    ? undefined
    : spread.positions.length;

  // 固定牌阵：张数必须等于 positions.length
  if (expectedCount !== undefined && input.cards.length !== expectedCount) {
    context.addIssue({
      code: "custom",
      message: `牌阵 ${spread.name} 需要恰好 ${expectedCount} 张牌，实际 ${input.cards.length} 张`,
      path: ["cards"],
    });
  }

  // 自由形式：张数必须在 countRange 内
  if (expectedCount === undefined) {
    const [min, max] = [1, 13]; // 应从 spread 元数据读取
    if (input.cards.length < min || input.cards.length > max) {
      context.addIssue({
        code: "custom",
        message: `自由形式牌数必须在 ${min} 到 ${max} 之间`,
        path: ["cards"],
      });
    }
  }

  // 位置编号校验
  const positions = input.cards.map((c) => c.position).sort((a, b) => a - b);
  const expectedPositions = Array.from({ length: input.cards.length }, (_, i) => i + 1);
  if (positions.join(",") !== expectedPositions.join(",")) {
    context.addIssue({ code: "custom", message: "位置编号必须从 1 开始连续覆盖", path: ["cards"] });
  }

  // 唯一性
  if (new Set(input.cards.map((c) => c.id)).size !== input.cards.length) {
    context.addIssue({ code: "custom", message: "Cards must be unique", path: ["cards"] });
  }

  // 评分规则：scoring 仅在 supportsScoring 牌阵 + naturalFlow=false 时合法
  if (input.scoring && (!spread.supportsScoring || input.naturalFlow)) {
    context.addIssue({
      code: "custom",
      message: "评分仅支持非自然流模式下的可评分牌阵",
      path: ["scoring"],
    });
  }

  // calculation 与 scoring 一致
  if (input.scoring && !input.calculation) {
    context.addIssue({ code: "custom", message: "scoring=true 时必须提供 calculation", path: ["calculation"] });
  }
  if (!input.scoring && input.calculation) {
    context.addIssue({ code: "custom", message: "scoring=false 时不应提供 calculation", path: ["calculation"] });
  }

  // patterns 与自然流一致
  if (input.naturalFlow && !input.patterns) {
    context.addIssue({ code: "custom", message: "naturalFlow=true 时必须提供 patterns", path: ["patterns"] });
  }
  if (!input.naturalFlow && input.patterns) {
    context.addIssue({ code: "custom", message: "naturalFlow=false 时不应提供 patterns", path: ["patterns"] });
  }
});
```

### 4.5 Runtime 层：`packages/runtime/src/interpretation-input.ts`

```ts
export function buildInterpretationInput(options: {
  readingId: string;
  question: string;
  mode: "manual" | "random";
  spreadId: string;
  naturalFlow: boolean;
  scoring: boolean;
  selected: readonly DeckEntry[];
  cards: readonly TarotCard[];
  metadata: ContentMetadata;
}): TarotInterpretationInput {
  const spread = getSpreadById(options.spreadId);
  if (!spread) throw new Error(`Unknown spread: ${options.spreadId}`);

  const expectedCount = spread.positions.length || options.selected.length; // freeform 用实际张数
  if (options.selected.length !== expectedCount && spread.positions.length > 0) {
    throw new RangeError(`Spread ${spread.id} requires ${expectedCount} cards`);
  }

  // positionName 从 spread.positions 取，freeform 用"第 N 张"或留空
  const selectedCards = options.selected.map((entry, index) => {
    // ... 原有字段构造
    const positionName = spread.positions[index]?.name ?? `第 ${index + 1} 张`;
    return { /* ... */ positionName };
  });

  const calculation = options.scoring
    ? calculateMomentumValue(selectedCards.map((c) => c.score.final))
    : undefined;

  const patterns = options.naturalFlow
    ? aggregatePatterns(/* 映射 selectedCards + 完整牌信息 */)
    : undefined;

  return interpretationInputSchema.parse({
    // ...
    spread: { id: spread.id, name: spread.name, positions: spread.positions, supportsScoring: spread.supportsScoring },
    naturalFlow: options.naturalFlow,
    scoring: options.scoring,
    calculation,
    patterns,
    // ...
  });
}
```

### 4.7 Providers 层：`packages/providers/src/model.ts`

这是**多端同步的关键**。当前桌面和移动共用此包，因此改一处即可覆盖两端。

- `outputSchema`（给模型用的 JSON Schema）必须动态生成，不能硬编码 `minItems: 5 / maxItems: 5` 和固定 `momentumInterpretation`/`valueInterpretation`。
- `JSON_STRUCTURE_PROMPT` 必须动态生成，根据 `input.naturalFlow` 和 `input.scoring` 选择字段说明。
- system prompt 的「固定分值」文案需要条件化：scoring=true 时保留，scoring=false 时改为「画面优先/能量流/整体读」等自然流/最后一舞风格文案。

建议重构为函数：

```ts
export function buildOutputSchema(input: TarotInterpretationInput) {
  const base = {
    type: "object" as const,
    additionalProperties: false,
    required: ["headline", "questionReflection", "cards", "storyline", "actionAdvice", "reflectionQuestion", "disclaimer"],
    properties: {
      headline: { type: "string" },
      questionReflection: { type: "string" },
      cards: {
        type: "array",
        minItems: input.cards.length,
        maxItems: input.cards.length,
        items: {
          type: "object",
          additionalProperties: false,
          required: ["cardId", "position", "meaning", "connectionToQuestion"],
          properties: { /* ... */ },
        },
      },
      storyline: { type: "string" },
      actionAdvice: { type: "array", minItems: 2, maxItems: 3, items: { type: "string" } },
      reflectionQuestion: { type: "string" },
      disclaimer: { type: "string" },
    },
  };

  if (input.scoring) {
    base.required.push("momentumInterpretation", "valueInterpretation");
    base.properties.momentumInterpretation = { type: "string" };
    base.properties.valueInterpretation = { type: "string" };
  }

  if (input.naturalFlow) {
    base.required.push("energyFlow", "overallTheme", "patterns", "holisticReading");
    base.properties.energyFlow = { type: "string" };
    base.properties.overallTheme = { type: "string" };
    base.properties.patterns = { type: "array", items: { type: "string" } };
    base.properties.holisticReading = { type: "string" };
  }

  return base;
}

export function buildJsonStructurePrompt(input: TarotInterpretationInput): string {
  // 根据 input.naturalFlow / input.scoring 拼接字段说明
}

export function buildSystemPrompt(input: TarotInterpretationInput): string {
  const style = input.naturalFlow
    ? "你是...画面优先、牌间能量流、直觉引导、整体叙事..."
    : "你是...克制、生活化、有共情力..."; // last-dance 风格
  const scoringHint = input.scoring ? "严格根据牌面、固定分值和方法论输出。" : "不使用固定分值，从画面与整体能量出发解读。";
  return `${style}\n${scoringHint}\n\n${buildJsonStructurePrompt(input)}`;
}
```

然后 `OpenAICompatibleProvider.interpret` 和 `ChatCompletionProvider.interpret`/`interpretStream` 都改为调用 `buildOutputSchema(input)` 和 `buildSystemPrompt(input)`。

### 4.8 Desktop / Mobile UI

桌面端和移动端各自需要：

1. **新建/开始解读页**：
   - 牌阵选择器（下拉/网格）。
   - 「自然流模式」开关（toggle）。
   - 「启用动量/价值评分」开关（仅当牌阵为 `five_card_timeline_v1` 且自然流关闭时可用）。
   - 根据牌阵动态显示 `已选 X / N`。

2. **选牌页**：
   - 上限改为 `spread.positions.length` 或自由形式 `countRange`。
   - 自由形式允许用户随时点「开始解读」（不必选满）。
   - 固定牌阵仍需选满才能确认。

3. **揭晓/解读页**：
   - `CardRevealStage` 已按 `cards.length` 自动缩放布局，只需把张数传对。
   - 输出渲染按返回字段条件化：
     - scoring=true：显示 `momentumInterpretation` / `valueInterpretation`。
     - naturalFlow=true：显示 `energyFlow` / `overallTheme` / `patterns` / `holisticReading`。
     - 否则：基础 storyline + actionAdvice。

4. **历史记录页**：
   - 读取 `interpretation.naturalFlow` / `interpretation.scoring` 决定渲染路径。
   - 旧记录无这两个字段时，按 `scoring=true` + `naturalFlow=false` 默认（兼容当前行为）。

```ts
const spreadId = reading.spreadId ?? "five_card_timeline_v1";
const naturalFlow = reading.naturalFlow ?? false;
const scoring = reading.scoring ?? true;
```

### 6.3 云端同步

如果历史记录通过 R2 同步，旧数据结构对方也能正常解析（新增字段 optional，旧字段保留）。

## 8. 风险点

1. **Provider JSON Schema 动态化后 strict 模式**：`additionalProperties: false` 下，optional 字段不存在时不能出现在 `required` 里。`buildOutputSchema` 必须严格按输入状态决定 `required`，否则模型返回的 JSON 解析会失败。
2. **移动端和桌面端 UI 改动量**：虽然模型层共享，但两端 UI 都需要新增牌阵选择页和条件渲染，是主要工时。
3. **自由形式张数 UX**：1 张和 13 张的交互差异大，需要明确的「开始解读」按钮而不是自动满额触发。
4. **旧记录兼容**：旧记录默认 `scoring=true` 是安全的；但如果未来把默认行为改成 `scoring=false`，需要显式迁移。
5. **评分公式仍是 5 张硬编码**：`scoring.ts` 本身不改，但任何新的 5 张牌阵如果想开评分，都需要重新评估公式是否适用（目前是时间流专属加权）。
