# 产品体验与选牌交互

> 本文描述完整第一版的目标体验。当前可运行版本已经连通问题、选牌、计算、解读与历史，但部分确认流程、键盘/Pointer Events 交互、搜索和导出尚未实现；详见 [当前实现状态](00-implementation-status.md)。

## 1. 桌面整体布局

产品借鉴本地 Agent 桌面应用的会话结构，但使用塔罗视觉语言：

应用外壳遵循 Astryx/Maka 的桌面工作区风格：紧凑、清晰、克制、可检查。黑金宇宙视觉集中在抽牌舞台，不覆盖会话列表、设置、输入框和工具详情等工作界面。

```text
┌────────────────┬─────────────────────────────────────────┐
│ 会话与历史      │ 当前会话                                │
│                │                                         │
│ + 新的解读      │ 用户问题                                │
│                │ Agent 回应                              │
│ 今天            │                                         │
│ · 事业方向      │ 抽牌舞台 / 五张牌 / 解读正文            │
│ · 感情状态      │                                         │
│                │ ▸ 查看抽牌与计算过程                     │
│ 更早            │                                         │
│                │                                         │
│ ⚙ 设置          │ 输入框                                  │
└────────────────┴─────────────────────────────────────────┘
```

左侧负责：

- 新建解读；
- 历史会话；
- 搜索、重命名和删除；
- 设置入口。

中央负责：

- 用户问题；
- Agent 的必要追问；
- 抽牌交互；
- 翻牌动画；
- 逐牌和综合解读；
- 可折叠的工具调用与数值过程。

界面组件优先使用 Astryx 基础组件和统一主题令牌。没有明确所有权边界的区域不额外套卡片、玻璃面板或阴影。

## 2. 新建解读流程

### 2.1 输入问题

首屏显示旋转缓慢的魔法阵、问题输入框和简短提示：

> 把此刻最想弄清楚的事情，交给牌面。

问题需要有明确对象，例如事业、关系、财务或某个选择。Agent 可以在问题过于宽泛时追问一次，但不能把流程变成漫长访谈。

追问发生在进入牌桌之前，以输入框上方的内联 Agent 消息呈现：

1. 用户提交原始问题；
2. Runtime 判断是否需要澄清；
3. 如需澄清，显示一次内联追问并保留原始问题；
4. 用户回答后生成 `resolvedQuestion`；
5. 原始问题、追问、回答和最终问题都写入会话；
6. 进入牌桌后不再追问，避免打断抽牌仪式。

用户可以跳过追问并直接使用原始问题，但界面需提示问题越具体，解读越容易落到现实情境。

### 2.2 选择抽牌方式

用户进入牌桌后有两个入口：

- `亲自选牌`：默认方式；
- `交给命运`：程序随机抽取五张。

两种方式共享同一套牌库、正逆位规则、计算模型和解牌流程。

## 3. 自主选牌

### 3.1 洗牌

进入牌桌时程序生成一次洗牌结果：

- 78 张牌产生固定的暗牌顺序；
- 每张牌的正逆位状态同时确定；
- 洗牌种子、牌序和方向暂存在当前草稿中；
- 确认前不向用户显示牌面身份；
- 同一次洗牌中，取消选择不会改变暗牌身份。

这样可以保证交互可复现，并避免取消选择时后台悄悄换牌。

### 3.2 左右滑动

牌背以水平卡带形式呈现：

- 鼠标滚轮可横向滚动；
- 按住拖动可以左右浏览；
- 可使用键盘方向键移动焦点；
- 当前悬停牌轻微抬升并发光；
- 首尾提供渐隐提示，表示仍可继续滑动。

第一版使用高性能的 2D/CSS 卡带即可。3D 弧形牌墙属于视觉增强，不阻塞核心流程。

Windows 第一版的主要输入是：

- 鼠标按住拖动：左右浏览牌组；
- 鼠标滚轮：横向滚动牌组；
- 鼠标点击：选择或取消牌；
- 键盘方向键：移动当前焦点；
- `Enter` 或 `Space`：选择当前聚焦牌；
- `Escape`：关闭弹层或取消当前未确认操作。

选牌组件统一使用 Pointer Events，不分别维护鼠标和触摸两套状态机：

```text
pointerdown
→ pointermove
→ pointerup / pointercancel
```

在 Windows 无触摸屏设备上，通过鼠标拖动完成实际操作，通过窄窗口和自动化模拟检查移动布局。真实手机触摸手感、惯性和安全区域留到移动端阶段使用真机校准。

### 3.3 选择规则

点击一张暗牌：

- 卡牌向上抬起；
- 出现金色边框；
- 显示选择顺序角标，如 `1/5`；
- 底部选择托盘增加对应牌背。

再次点击已选择牌：

- 取消该牌；
- 后续选择顺序自动前移；
- 仍然保持原洗牌结果。

限制规则：

- 最多选择五张；
- 未选满时确认按钮禁用；
- 选择五张后，其余暗牌降低亮度但仍可浏览；
- 用户必须先取消一张，才能换选另一张。

### 3.4 确认、清空与重新洗牌

底部固定操作栏显示：

```text
已选择 3 / 5    [清空选择]    [重新洗牌]    [确认五张牌]
```

- `清空选择`：取消当前五张选择，但保留本次洗牌；
- `重新洗牌`：清空选择并生成新种子、新牌序和新方向；
- `确认五张牌`：仅在选满五张时可用；
- 返回问题页时保留草稿，并询问是否放弃当前选择；
- 确认后不允许换牌，除非明确开始一次新的解读。

### 3.5 牌位顺序

五张牌的顺序按照用户点击顺序确定，而不是它们在牌带中的物理位置。

当前模型只规定越向右越接近当前状态，因此第一版牌位名称使用：

1. 较远背景；
2. 早期状态；
3. 中间状态；
4. 近期状态；
5. 当前状态。

未来可以增加其他牌阵，但不能在第一版混入不同语义。

## 4. 随机抽五张

点击 `交给命运` 后：

1. 生成一次洗牌；
2. 从洗牌后的牌堆依次取前五张；
3. 显示五张牌背和“确认本次抽牌”；
4. 用户可以确认，或重新随机一次；
5. 确认后进入与自主选牌完全相同的流程。

随机模式也必须保存洗牌种子和牌序，不能只保存最终牌名。

## 5. 翻牌与解读

确认后：

1. 牌组退到背景；
2. 五张牌按选择顺序飞到中央；
3. 金色粒子聚拢；
4. 五张牌依次 3D 翻转；
5. 逆位牌以倒置牌面显示；
6. 每张牌显示牌名、正逆位和一句短提示；
7. 第五张揭示后启动 Agent 解牌；
8. 解读正文流式出现。

如果此时断网、模型未配置或服务暂时不可用：

- 五张牌和本地计算仍然正常完成；
- 当前记录保存为“等待 AI 解读”；
- 用户可以关闭应用；
- 恢复联网后从历史记录继续解读；
- 继续解读复用原牌面和计算，不重新抽牌。

动画必须允许跳过。用户选择“减少动态效果”时，使用淡入和缩放替代大幅运动及粒子爆炸。

## 6. 结果页面

结果分为四层：

### 6.1 五张牌

水平展示五张牌及其牌位。点击任意牌可展开：

- 视觉描述；
- 关键符号；
- 正逆位依据；
- `S、D、N、x`；
- 与用户问题的关系。

### 6.2 整体故事线

AI 说明五张牌如何从较远背景发展到当前状态，包括人物朝向、牌面互动和转折关系。

### 6.3 当前动量与路径价值

用魔法罗盘或双轴仪表展示：

- 当前动量 `M`；
- 当前路径价值 `V`；
- 阈值标签；
- 自然语言解释。

数值不能脱离文本单独呈现。

### 6.4 行动建议

最终包含：

- 两至三个可执行建议；
- 一个反思问题；
- 象征性自我探索声明；
- `保存`、`重新开始` 和 `导出`。

第一版导出以 Markdown 为准，包含问题、五张牌、结构化解读、版本信息，并允许选择是否附加评分和公式过程。分享长图属于后续视觉增强，不阻塞第一版。

## 7. 会话与历史

历史记录打开后直接读取本地结果，不重复调用 AI。需要保存足够信息以完整重放：

- 原始问题；
- 抽牌方式；
- 洗牌种子；
- 完整牌序；
- 被选牌及点击顺序；
- 正逆位；
- 全部评分；
- 公式版本；
- 模型与提示词版本；
- 工具调用过程；
- 最终解读。

第一版历史搜索范围为会话标题、用户问题和五张牌名。数据规模较小时使用普通索引和 `LIKE`，不提前引入 FTS5；解读全文搜索等真实需要出现后再迁移。

## 8. 可选实验：摄像头魔法手势

摄像头手势不是第一版功能，也不能替代鼠标、键盘或未来的触摸操作。

如果后续增加，建议仅作为可关闭的沉浸模式：

```text
左右挥手 → 浏览牌组
捏合手指 → 选择当前牌
张开手掌 → 取消当前选择
保持确认手势 2 秒 → 进入确认倒计时
```

安全与交互约束：

- 首次开启前明确请求摄像头权限；
- 默认关闭，不随应用启动自动开启；
- 显示摄像头工作状态和立即关闭入口；
- 识别结果先变成可见预览，不直接提交；
- 最终确认需要持续手势、倒计时和撤销机会；
- 识别失败或光线不足时自动回退到鼠标；
- 摄像头帧默认只在本机内存中处理，不写入数据库；
- 不保存照片或视频；
- 不允许手势绕过“五张牌已选满”的状态校验。
