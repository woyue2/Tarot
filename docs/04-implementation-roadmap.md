# 开发路线与验收标准

> 本文保留完整第一版的任务和验收标准，不以勾选方式重复维护完成度。各阶段当前均为“部分实现”，具体差距和更新时间见 [当前实现状态](00-implementation-status.md)。

## 1. 总体策略

先完成一条真实可用的垂直流程，再增强视觉：

```text
桌面窗口
→ 本地数据库
→ 问题输入
→ 自主/随机选五张
→ 确认与翻牌
→ 确定性计算
→ AI 解读
→ 历史恢复
→ 动画与打包
```

自主选牌从第一版开始实现。原因是它会影响草稿状态、洗牌持久化、牌序、Agent 输入和 UI，不适合作为完成随机模式后的补丁。

高级 3D 牌墙不是第一阶段阻塞项。先实现可靠的水平卡带，再逐步升级视觉。

## 2. Phase 0：内容与规则规范化

任务：

- 生成统一 `cards.json`；
- 定义稳定 `card_id` 与规范牌名、别名；
- 指定五份清理后的视觉 `.md` 为 source of truth，排除 `*_结果.txt`；
- 将原始图片构建为 `resources/cards/{card_id}.webp`；
- 校验 78 张牌和牌背都存在；
- 建立牌名别名映射；
- 校验 `card-scores.csv` 的 78 张牌和 156 个方向评分；
- 将 Python 公式移植为 TypeScript；
- 原样实现 `roundHalfAway`，为正负半值、序位分、单牌分、`M` 和 `V` 编写测试；
- 固定 `formula_version`；
- 固定 `score_table_version`、`content_version` 和 `methodology_version`；
- 明确五个牌位名称；
- 把方法论整理为稳定、精简且版本化的提示词资源；
- 生成 `content-manifest.json` 并记录源文件摘要。

验收：

- `cards.json` 恰好包含 78 张唯一牌；
- 每张牌能找到图片和视觉描述；
- 每张牌都有正位和逆位固定评分，不存在运行时临时评分；
- TypeScript 对 156 条评分和代表案例产生与 Python 相同结果；
- 名称差异不会导致图片或评分查找失败。
- 相同输入能够生成字节稳定的运行时 JSON；
- 开发与打包资源解析均只通过 `AssetResolver`。

## 3. Phase 1：Windows 桌面基础

任务：

- Electron、React、Vite、TypeScript 工程；
- 确定 pnpm 作为唯一包管理器并提交 `pnpm-lock.yaml`；
- 接入 Astryx reset、基础组件和 Tarot Theme；
- 建立 Storybook 或等价组件展示页；
- 主进程、preload、renderer 边界；
- 左侧会话栏与中央对话区；
- SQLite 初始化和迁移；
- 新建、重命名、删除本地会话；
- 设置页；
- `safeStorage` 保存 API Key；
- 首次启动模型设置引导；
- 模型连接测试；
- SQLite schema 迁移、迁移前备份和恢复基础；
- 开发与生产资源路径适配。

验收：

- Windows 上可以启动和关闭；
- 关闭后重新打开，会话仍然存在；
- Renderer 无法直接读取 API Key；
- 数据库迁移重复执行不会损坏数据；
- 模型连接失败时给出可理解的错误。
- 用户首次启动可以完成 API Key、模型和连接测试，不依赖 Phase 5；
- 数据库迁移前能够生成有效备份；
- 按钮、输入框、弹窗、菜单、提示和焦点状态均来自统一 Astryx 组件路径；
- 组件展示页覆盖默认、悬停、聚焦、禁用、加载和错误状态。

## 4. Phase 2：选牌状态机

任务：

- 创建问题与解读草稿；
- 生成洗牌种子和固定暗牌顺序；
- 水平牌背卡带；
- 基于 Pointer Events 的鼠标拖动，并为触摸与触控笔复用；
- 滚轮和键盘浏览；
- 点击选择/取消；
- `1–5` 顺序角标；
- 五张上限；
- 清空选择；
- 重新洗牌；
- 选满确认；
- 随机抽五张入口；
- 确认后锁定牌序。

验收：

- 未选满五张不能确认；
- 取消第二张后，原第三至第五张顺序正确前移；
- 清空选择不改变洗牌顺序；
- 重新洗牌会改变种子和牌序；
- 确认后无法换牌；
- 恢复未完成草稿时，牌序和选择状态不变；
- 相同种子能够复现完整牌堆。
- 鼠标按下后拖出窗口或收到 `pointercancel` 时不会残留拖动状态；
- 不依赖滚轮也能完成全部选牌流程；
- 360px 窄窗口下可以浏览、选择、取消并确认五张牌。

## 5. Phase 3：Tarot Agent 垂直流程

任务：

- Agent Runtime；
- 固定运行步骤与最终解读模型边界；
- 五张牌最终解读输入契约；
- 模型流式输出；
- 结构化结果校验；
- 已知评分读取；
- 确定性计算；
- 工具调用与结果事件；
- 取消与错误重试；
- 离线“等待 AI 解读”状态；
- 网络、认证、限流、超时、取消、输出校验和数据错误分类；
- mock 模型和固定流式响应测试夹具；
- 保存完整解读。

验收：

- AI 不能修改已确认牌面；
- AI 不能覆盖程序计算结果；
- 最终解读调用前必须验证五张牌、位置、确认状态、评分与公式版本；
- 最终 AI 输出只保存解释性字段，牌名、图片、方向和数值始终从本地事实读取；
- 任一固定评分缺失时停止，不允许 AI 临时赋分；
- 断网或 API 错误不会导致重新抽牌；
- 断网时可以完成翻牌和本地计算，并保存为“等待 AI 解读”；
- 重试复用同一组牌和数值；
- 重试复用同一 `readingId`，但创建新的 `runId`；
- 结构化结果不合法时不会把记录标记为完成；
- 历史记录可以重放工具过程与最终解读。
- 流式 delta 不逐 token 永久写入 SQLite，完成后只保留必要事实和最终结果。

## 6. Phase 4：视觉体验

任务：

- 黑金宇宙背景；
- 魔法阵；
- 卡牌悬停与选择动画；
- 五张牌飞入中央；
- 3D 翻转；
- 正逆位展示；
- 粒子爆发；
- 流式解读排版；
- 动量—价值魔法罗盘；
- 减少动态效果设置；
- 跳过动画；
- Astryx 设计令牌与产品组件视觉检查；
- 空状态、加载、错误、确认和危险操作状态的统一设计；
- 牌带阶段只加载牌背；确认后仅解码五张被选牌的正面资源；
- 建立可重复的 Windows 性能基线记录。

验收：

- 动画不会阻止取消 AI 请求；
- 跳过动画后仍能进入正确状态；
- 窗口缩放时牌面和正文不重叠；
- 开启减少动态效果后不出现大幅运动；
- 工作区 UI 不出现无意义的卡片嵌套、持续霓虹描边或装饰性玻璃层；
- 金色粒子和光效只在抽牌仪式与关键状态反馈中出现；
- 基线设备上拖动和翻牌目标为 60 FPS，持续一秒以上不得低于 45 FPS；
- 点击或键盘选择后的可见反馈在 100 ms 内出现；
- 首次窗口显示到可输入状态目标不超过 3 秒；
- 关闭粒子或减少动态效果后，低性能设备仍可完成全部流程；
- 使用合成 10,000 条历史记录时，标题、问题和牌名搜索目标在 100 ms 内返回。

## 7. Phase 5：历史、导出与打包

任务：

- 历史搜索、重命名、删除；
- 已完成、等待解读、失败与草稿筛选；
- 标题、问题和牌名搜索；
- Markdown 导出及可选计算附录；
- SQLite 自动备份、手动备份和恢复；
- 日志脱敏、轮转和诊断信息入口；
- Windows 安装包；
- Windows 便携版；
- 未签名个人版的 SmartScreen 安装说明。

验收：

- 安装后不需要 Node.js 或 Python；
- 卸载前可明确选择是否保留本地数据；
- 导出不包含 API Key；
- 备份恢复后历史牌序和解读一致；
- 备份恢复失败不会覆盖当前数据库；
- 安装版和便携版默认读取相同的 `%APPDATA%\TarotAgent\`；
- 日志轮转后不会无限增长；
- 新机器首次启动能完成模型设置并运行一次解读。

## 9. Future：移动端与摄像头手势

这些能力不属于 MVP，也不阻塞 Windows 第一版：

- 创建 Capacitor 移动容器；
- 实现移动 SQLite 与安全凭据适配器；
- 使用 Android/iOS 真机校准触摸、惯性滚动和安全区域；
- 可选的摄像头魔法手势输入；
- 摄像头权限、识别状态、失败回退和隐私提示；
- 手势确认倒计时与撤销机制。

摄像头手势必须通过与鼠标相同的选牌状态机，不能直接写入 `selectedIndexes` 或触发不可撤销确认。

> 手机端的现状盘点、缺口、UI 考量与阶段化建议，详见 [手机版本后续准备计划](07-mobile-version-plan.md)。

## 10. 完成定义

第一版完成必须同时满足：

1. 可以在 Windows 本地安装和启动；
2. 不需要登录和远程数据库；
3. 可以自主滑动并选出五张牌；
4. 确认前可以取消和重选，确认后结果固定；
5. 可以选择随机抽五张；
6. 五张牌能够正确翻开并显示正逆位；
7. 程序能够输出可复现的评分、动量和价值；
8. AI 能生成结构化、生活化且不过度断言的解读；
9. 所有数据保存在本地 SQLite；
10. 关闭应用后能够恢复历史解读；
11. API Key 不暴露给 Renderer 或日志；
12. 核心单元测试、集成测试和 Windows 冒烟测试通过。
13. 78 张牌、156 条评分、视觉描述和图片映射全部通过生成校验。
14. 断网后可以保留已确认牌面，并在恢复联网后继续同一次解读。
